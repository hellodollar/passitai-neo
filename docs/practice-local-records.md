# 本地做题记录

## v2 结构

类型定义位于 `src/types/practice-record.ts`，读写、迁移及恢复逻辑位于 `src/utils/practice-record.ts`。

存储键为 `passitai:practice-record:v2:<encoded userId>:<source>:<encoded paperId>`。用户和题集 ID 使用 `encodeURIComponent`，训练来源分为 `practice`、`favorites`、`wrong-questions`。同一个 `fav:` 虚拟题集在收藏、错题中使用不同存储键。

| 字段 | 用途 |
| --- | --- |
| `version` | 存储结构版本，当前为 2 |
| `clearToken` | 本地清理代际，阻止旧页面及迟到响应回写；此前 v2 缺失时默认空串 |
| `userId`、`paperId`、`source` | 账号、题集及来源隔离 |
| `subjectId`、`paperType` | 科目、练习分类；收藏/错题聚合训练的 `paperType` 为 `null` |
| `answers` | 已确认的答案，每题保留题目指纹 |
| `inputs` | 尚未确认的输入，不计为已答 |
| `currentQuestionId` | 恢复当前做题位置 |
| `startedAt`、`savedAt` | 开始时间及最近保存时间 |
| `answerRevision` | 已确认答案版本；输入、切题不会递增，答案或指纹变化时递增 |
| `pendingSubmission` | 待提交 ID、答案版本及固定请求快照 |
| `lastSubmission` | 最近成功交卷的 ID、答案版本及交卷时间；同版本再次交卷复用报告 |

交卷数据和本地答案分开保存。输入、答案及选项数组保存时复制，避免页面继续输入改变已经保存的请求快照。答案版本变化后不能继续使用旧版本的待提交 ID。

## v1 迁移

1. 打开题集并取得真实科目、练习分类后，优先读取对应的 v2 记录。
2. 没有有效 v2 记录时，读取 `passitai:practice-draft:v1:<userId>:<paperId>`。
3. 校验版本、账号、题集、时间和答案结构；保留有效答案、未确认输入、位置、时间及待提交 ID，补齐真实分类信息。
4. 写入 v2 并读回确认落盘后，再移除原 v1 键。写入失败时仍返回可恢复的内存记录，原草稿保留以便重试；旧键删除失败时继续优先读取新键。
5. 继续按当前题集及题目指纹恢复，剔除失效答案，并在页面保存时回写。

迁移按题集首次访问进行，不能在不知道题集所属科目、分类时猜测这些字段。未访问的 v1 草稿继续保留。

旧集合草稿没有来源字段，无法判断原本来自收藏还是错题。迁移时只归属首次打开的训练来源，不复制给另一来源；原键删除失败时也会检查另一来源是否已经完成迁移。旧待提交 ID 没有请求快照，迁移后暂时保留 `payload: null`，题目恢复后的首次保存补齐请求数据，保留原始提交 ID。

登出清理当前账号的所有 v2 记录以及尚未迁移的 v1 草稿，不清除其他账号的本地数据。

## 交卷与恢复（第二阶段）

- 已答完、部分作答、零作答均可交卷并进入练习报告；空题集不能交卷。未确认的多选、文字输入保留在本地，但不计入本次交卷。
- 交卷成功只登记 `lastSubmission`、移除匹配的 `pendingSubmission`，不删除答案、输入、位置或开始时间。再次打开题集恢复原作答，未答题可继续补答；已确认题目沿用原有不可重答交互。
- 当前答案版本与最近成功交卷版本相同，直接打开原报告，不重复调用提交接口；补答确认或题目指纹变化后，以新 ID 提交新快照。报告始终读取指定交卷 ID 的服务端作答，不读取后续本地答案。
- 请求前保存待提交 ID 与固定请求快照。失败后重试沿用相同 ID、答案和开始时间；提交按钮防重复点击，提交中不能通过遮罩或 Escape 关闭确认框。
- 重入时立即恢复本地作答；对尚不确定结果的待提交 ID 在后台核对。已成功则登记提交元信息，不自动跳报告；核对失败则保留快照供下次交卷重试。
- 路由或账号变化后，旧异步响应不能回写当前页面或触发报告跳转；旧版本响应也不能覆盖新版本的答案、待提交快照或报告。
- 收藏和错题聚合练习不提供交卷，继续按来源独立保管本地作答。

## 首页进度与清理（第三阶段）

- 首页继续获取题集目录、科目和题目总数，题集 `answeredCount` 与进度条由本地已确认答案回填；未确认输入不计已答，无本地记录为 0，不使用接口旧进度。
- 按账号、来源、科目、题集和分类匹配记录，单题集已答数不超过目录题数，分类合计由子题集已答数相加。目录没有题目 ID/指纹，首页不能逐题校验题目变化；进入题集时仍执行原有指纹校验，再回写修正进度。
- 首页取得真实科目和分类后，可按已加载目录迁移这些题集的 v1 草稿，不额外调用题集详情或服务端作答接口。尚未知分类的旧记录不猜测迁移。
- 单题集清理入口位于答题卡的清理图标，适用于普通题集、收藏练习和错题练习；首页和“我的”均不提供记录管理或批量清理入口，本地作答保存、恢复和首页进度回填保持不变。
- 底层保留分类与全部清理能力，暂不提供手动入口；登出继续清除当前账号的本地记录。单题集手动清理使用确认对话框，不删除服务端报告或收藏/错题收录。
- 清理先持久化独立的屏障键 `passitai:practice-record-clear:v1:<encoded userId>:<scope>`，再删除原数据。全部、分类、单题集屏障独立，防止不同清理操作相互覆盖；保留这些无答案内容的键用于失效判断，不能随记录一起删掉。
- v2 增加兼容字段 `clearToken`；旧 v2 无该字段按空串读取，不丢失原作答。新记录绑定当前屏障，读写前后检查代际；已清理的旧记录即使删除失败、被旧标签页写回或收到迟到交卷响应也不再有效。扫描后出现的新代际记录不会被误删。
- v1 没有分类和代际，无法按分类物理删除尚未识别的旧键；已清理分类在后续迁移时拒绝恢复这些旧答案，清除全部时统一移除旧键。收藏/错题共用的旧键被任一来源清理后，也不迁移到另一来源。
- 当前页面通过本地事件同步，其他同源标签页通过 `storage` 事件同步；重新获得焦点或回到前台时补检查。打开的答题页立即重置受影响的作答、输入、位置、待提交及上次报告元信息，停止延迟保存和切题，失效在途请求。无关科目分类、来源及账号不受影响。
- 本地存储故障时手动清理明确报错，不假装成功；登出继续尽力删除本账号记录。清理后空白首题不立刻保存新记录，输入、切题或交卷时再保存。

## 后续接入边界

答题页已使用 v2 读写与恢复，训练来源发生变化时重新加载对应记录。

首页本地进度、手动清理和跨标签页清理同步已接入。不改动收藏和错题的服务端收录记录；不合并多个标签页同时编辑同一题集的新答案。

原有 `startedAt` 被完整保留；有效作答时长统计尚未改动，不应将自然时间差描述为有效练习时长。

## 验证

- 本地记录迁移、交卷快照、重复交卷、补答新版本、失败重试、迟到响应、首页回填、清理隔离及跨标签通知等自动测试覆盖。
- 类型检查、ESLint、Oxlint 与生产构建通过。
- 隔离接口浏览器实测：部分作答进入报告；重入保留答案；未补答复用报告且不重复 POST；多选输入与位置刷新保留；补答生成新报告；文字确认后完整交卷。
- 本地现有测试账号登录失败，因此上述交互验证使用临时隔离接口，没有向真实后端写入练习数据。真实后端联调仍需有效测试账号。
- 第三阶段共 45 项自动测试通过。隔离浏览器确认：首页忽略接口旧进度，作答后显示本地 1/3；单题集确认框范围正确，取消不会清理。原分类管理入口已按后续要求移除。清理执行与跨标签失效保护已有自动测试覆盖；浏览器点击确认清理的联测待用户授权临时测试数据删除。
